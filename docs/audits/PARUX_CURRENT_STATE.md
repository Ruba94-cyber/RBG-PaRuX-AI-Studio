# PaRuX current state (audit baseline)

> Generated from the structured output of nine read-only domain audits (see `docs/audits/parts/*.md` for the narrative evidence).
> Evidence levels: **static** = code read, **unit_tests** = named automated tests exist (not necessarily executed by the auditor), **e2e_real** = a recorded real run, **none** = no evidence.
> The audit was static: nothing was built, run or fetched by the auditors. Statements about Locally Uncensored (LU) describe observable behaviour in the auditors' own words; no LU code is reproduced (LU is AGPL-3.0, PaRuX is MIT).

Baseline: branch `feature/parux-competitive-integration-20261019` at the audited commit (Agent Platform V2 + local-first hardening; the unmerged BIC line was audited separately and is marked `mainOnly`).

## Model discovery, catalog and capabilities

PaRuX's model discovery and download layer is strong on state and safety: a bounded candidate registry, hardened Hugging Face fetch, streamed SHA-256 with provenance, licence declaration and consent, and a geometry-based fit estimate. The catalogue pipeline has three gaps against LU that matter most. Split GGUF sets are not grouped, so one part can be presented as a model (P0). Vision projectors are not paired on download and rely on two hard-coded files (P1). There is no read-only import of existing Ollama or LM Studio stores (P1). Two PaRuX concepts are duplicated (fit estimators, capability classifiers, plus two quant parsers), and on HEAD auto-assign can silently overwrite a user's role choice. The fix for that and the BIC-16 promotion gate exist only on the local main branch, and were read with git show and git diff only. Evidence is static reading plus unit-test names; no test was executed, no build was run, and nothing was checked against the network. Part file: see partFile (96 lines, not committed).

**Verified strengths of PaRuX in this area**

- Candidate registry with bounded retention, cooldowns, deferred notices and explicit refresh (src/PaRuX.Server/ModelDiscoveryService.cs:8-9, 26-231; ModelDiscoveryServiceTests, 18 facts).
- Hardened discovery fetch: HTTPS only, official host, no redirects, size and time caps (src/PaRuX.Server/HuggingFaceModelDiscoveryProvider.cs:83-138).
- Streamed SHA-256 verification and a provenance manifest for downloads (src/PaRuX.Server/ModelDownloadService.cs:1060-1150, 776-810).
- Declared licence carried on the candidate, with a consent prompt and review rules (src/PaRuX.Contracts/ModelDiscoveryContracts.cs:16; src/PaRuX.App/Views/ModelLicenseConsentPrompt.cs).
- Physics-based fit estimate using GGUF KV geometry and explicit multi-GPU split reporting (src/PaRuX.App/Services/ModelHardwareFitEstimator.cs:64-130).
- GGUF header reader with a bounded cache and hostile-file tests (src/PaRuX.Intelligence/GgufMetadataReader.cs:49-83; GgufMetadataCacheTests 6 facts, GgufHostileFileTests 5 facts).
- Uncensored content is never the standard starter (src/PaRuX.Server/FirstModelAdvisor.cs:313-316).
- Empirical per-role capability scoring from profiler results, kept separate from name hints (src/PaRuX.Server/ModelCapabilityScorer.cs:22-85).

## Download manager

Clean-room audit of the downloads domain completed. LU v3.0.6 was read-only: no build, no tests, no network, no file of the installed app opened. PaRuX was read on the current worktree; tests were inspected by name and transport only, not executed. Part file: docs/audits/parts/downloads.md (uncommitted). Main PaRuX gaps: P0 the 30-minute total timeout on the transfer client (ModelDownloadService.cs:70) interrupts long downloads as cancelled or failed; P1 no physical-space check before or during download, no token support for gated repositories, no Gaming hard-off block in the worktree (the feature exists only on the main branch). PaRuX strengths: commit pinning, provenance manifest, licence review, partial identity for resume, cancellation that keeps the bytes. LU strengths: stall timeout instead of a total limit, space reservations, pause, shared bandwidth limit, tokens limited to the correct hosts, scan for orphaned partials. Neither has evidence of a real transfer: the conclusions are static or from unexecuted unit tests.

**Verified strengths of PaRuX in this area**

- Immutable commit revision required and pinned resolve URLs (ModelDownloadService.cs:601-682, 949-954)
- Per-file provenance manifest with atomic writes and fail-closed corruption handling (ModelDownloadProvenanceManifestStore.cs:40-191)
- Partial reuse only for the same source identity, kept in a sidecar (ModelDownloadService.cs:833-927)
- Cancel keeps bytes; remove is explicit and limited to terminal jobs (ModelDownloadService.cs:978-1016)
- Bounded concurrency: 3 global slots and one per destination (ModelDownloadService.cs:55-61, 1018-1040)
- Licence review gate with an affirmative, timestamped acknowledgement (ModelDownloadService.cs:683-745; ModelLicenseReviewRules.cs:17-29)
- Backup import rebinds provenance only after a SHA-256 match (ModelDownloadProvenanceManifestStore.cs:97-136, 251-276)
- Update detection by content hash rather than revision alone (HuggingFaceManagedModelUpdateSource.cs:1-22)
- Journal-based resume across Core restarts for PaRuX-started sources (App ModelDownloadResumeCatalog.cs:11-20)

## Runtime and engine management

PaRuX is ahead on the managed lifecycle: digest-gated installs with side-by-side tags, rollback, performance-gated promotion, identity-checked processes that never adopt foreign listeners, a managed ExLlamaV3 pack, and a VRAM-aware hot pool. LU is ahead on failure handling: a post-health output probe, CPU retry rungs, illegal-instruction diagnosis, candidate ports, pinned and verified installers, and a PyTorch channel chosen from GPU capability. LU also installs and controls Ollama, LM Studio, ComfyUI and Python; PaRuX does not manage competitor engines, by design. No P0 blocker was found. The P1 gaps are: no output sanity probe; launch tier chosen only from nvidia-smi; no CUDA-to-Vulkan fallback; fixed port 1234 (the LM Studio default); a hard-coded cu128 PyTorch index; and archive digests that come from the same GitHub channel as the asset. Nothing was built or run; LU was read only; no network was used. The part file is 110 lines and is not committed.

**Verified strengths of PaRuX in this area**

- Fail-closed archive pipeline: GitHub host and repo path, exact file name, mandatory SHA-256, 32 GiB cap, redirect allowlist (src/PaRuX.Server/RuntimeArtifactSecurityPolicy.cs:12, 21-92; RuntimeInstallService.cs:524-576).
- Side-by-side tags with rollback and reset endpoints (RuntimeInstallService.cs:191-220; Program.cs:2883-2893).
- Performance-gated promotion with first-install, accepted, rejected and deferred outcomes (RuntimeUpdateRegressionGuard.cs:90-201; RuntimeInstallContracts.cs:56-57).
- Process identity (id, start time, image path) with Verified, Foreign and Unverifiable states; kill-on-close job; foreign listeners never adopted (LocalAiProcessManager.cs:615-760, 1458; ManagedListenerOwnership.cs:7-29).
- Explicit ownership model PARUX_MANAGED, USER_MANAGED, SYSTEM_DETECTED with validation states and a skip choice (RuntimeInstallContracts.cs:65-98).
- Refusal to start the text runtime while a game is active (LocalAiProcessManager.cs, StartTextAsync first check; GamingActive at :269).
- VRAM-aware hot model pool through the llama-server router, with a route self-test (LocalAiProcessManager.cs:1291-1358).
- Managed ExLlamaV3 pack with a SHA-256 gate and install and cancel API (ExLlamaV3ManagedPackService.cs:245-261; RuntimeHardwareEndpointExtensions.cs:475-495).
- MSI baseline verified file by file against a SHA-256 manifest before use (BundledBaselineRuntimeBootstrap.cs:76-117).
- Read-only backend race against external endpoints that changes nothing external (RuntimeBackendRaceService.cs:10-14).

Its release-facing gaps: the MSI notice labels WindowsAppSDK MIT (it is Microsoft terms) and says llama.cpp and uv are not embedded (the staging script embeds them); the NuGet notice omits four shipped packages; the Full Offline bundle redistributes model weights with licence strings only; the Android build excludes META-INF Apache and LGPL licence texts. No LU identifiers appear on HEAD or main, so no LU code is in PaRuX. Line-referenced detail is in the part file, which is 154 lines.
