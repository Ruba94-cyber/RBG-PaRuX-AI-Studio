## 2. Method and evidence rules

- Symbol-first where Serena answered (C# overviews, `find_symbol` on `ModelDiscoveryService`). One `find_symbol` on `ModelRoleAutoAssigner` timed out, so that file was read in ranges. TypeScript and Rust were searched with narrow grep and read in decisive ranges.
- Evidence levels: `static` = code read, with line references. `unit_tests` = test classes present in `tests/PaRuX.Server.Tests`; counts are `[Fact]`/`[Theory]` attributes, and no test was executed. `e2e_real` = none found for this domain on HEAD. LU live tests (`hf-catalog-addresses.live`, `bundle-size-drift.live`) hit the network and were not run.
- No build, test, npm, cargo, or network access. No LU script or binary was run. LU's user data folder and installed application were not read.
- Specifications are in the auditor's own words. Identifiers, endpoints and file names are used as references only.

## 4. Top 10 prioritised proposals

Each proposal is a behavioural specification in the auditor's own words. Implementers should not need LU source.

1. **Shard-aware GGUF sets (P0, implement).** A split model is a group of files that share a stem, carry a part index and a total. Search shows one row per repo and quant. A download plan lists every part with size and digest, and refuses to start unless the whole set is present. The library shows one model per complete set, and an incomplete set with its missing parts. Edge cases: quant token after the part index; quant parts inside a subfolder; a projector never counted as a part; two quants in one repo.
2. **Projector pairing from repo data (P1, implement).** When the chosen repo lists a vision projector, the plan includes it as a second file with its own digest. A vision family with no listed projector shows a visible note. Import links a projector next to its model when both sit on one volume. Replace the hard-coded projector names with a manifest keyed by repo.
3. **Protect user role choices (P1, improve; port from main).** Auto-assign never changes a role the user set. It lists skipped roles with a reason. A failed write is reported, not swallowed. Add a test that a user override survives auto-assign.
4. **Promotion and rollback gate (P1, keep; port BIC-16 from main).** Promotion needs stored evidence, a launch that proves the file being promoted, a generation counter, a rollback route, and reconciliation after a crash. Port the main service only after HEAD's evidence store is reconciled with it.
5. **Read-only import of existing stores (P1, implement).** List GGUF files in the Ollama blob store and the LM Studio store at their default locations, read-only. Mark files already in the library. Link on the same volume. Copy only after consent that states the extra disk use. Never write into another application's store. A projector follows its model.
6. **One hardware-fit verdict (P1, improve).** Inputs: file bytes, optional GGUF geometry, the largest single accelerator or shared memory, usable RAM. Outputs: fits, tight, big, or unknown, plus a split-required flag where several devices would be needed. Unknown when hardware data is missing, never zero. One function serves Model Hub and Settings, with one short reason text.
7. **One capability taxonomy (P1, replace).** Inputs: repo id, file names, tags, alias. Outputs: a set of capabilities (coding, vision, embedding, reranker, reasoning, general chat), a content profile (standard or uncensored), and an evidence string. Boundary-aware tokens, a documented first-match order, and empirical scores kept separate from name-based hints.
8. **Search sort and grouping (P2, improve).** Sort by downloads or likes. One row per repo with a quant choice. Repos with no GGUF are hidden. Server error text is shown with a retry.
9. **Gated-repo token (P2, implement).** Optional token kept by Core. Sent only to huggingface.co. Never logged, and never sent on a redirect. A 401 or 403 names the setting to check.
10. **Single quant parser (P2, replace).** One table of recognised forms, the part index removed first, the most specific match wins, BF16 checked before F16, and an explicit unknown when nothing matches.

## 5. Risks

- A split model can be presented as a complete model (row 1). This is the highest-impact risk until shard grouping exists.
- Vision models answer as text-only without any warning (row 2).
- On HEAD, auto-assign can replace a user's role choice silently (row 3). The main branch fixes this, but a port changes behaviour that existing tests may assume.
- Two fit estimators can disagree on the same machine (row 6), which undermines trust in the Model Hub verdict.
- Substring classifiers mislabel models (rows 7, 12, 13). "dare" is a false positive for uncensored content.
- Copy-based import doubles disk use for large models (row 5).
- The Hugging Face API shape and limits are external. A change could break discovery silently unless a contract test pins the response shape.
- Seed repo ids are unverified offline. A wrong id is a dead end the user meets after clicking.
- BIC-16 logic exists only on local `main`. HEAD and main both changed `ModelHubView.cs` (the diff stat shows about 485 changed lines on main) and `ModelDiscoveryService.cs`, so a merge can conflict with HEAD changes.
- Several PaRuX facts rest on static reading. Unit tests were not executed, so pass status is unknown.
