# Video and audio: clean-room audit, PaRuX vs Locally Uncensored

Domain key: `video-audio`. Audit part file, not committed. Read-only pass: nothing was built, run or downloaded.

## 1. Scope

In scope: text-to-video, image-to-video, workflow handling, supported video and audio models with their component dependencies, memory and hardware limits, automatic dependency download, music and sound generation, TTS (including Piper voices), STT, continuous voice chat, barge-in, job management (queue, cancel, resume), previews and result galleries.

PaRuX side: `SpeechService` and the speech and voice services, `MediaEngineRaceService`, the Lifecycle Lab TTS path, the Create workspace, `docs/audio-model-decisions.md`, and BIC-13, including items that exist only on local `main`.

Out of scope: image-only generation except where it shares the ComfyUI runtime or the race; chat model quality; cloud providers.

## 2. Method and evidence rules

- PaRuX worktree: `<repo-worktree>`, branch `feature/parux-competitive-integration-20261019`, HEAD `117fcf7`. The only untracked path was `docs/audits/`.
- Local `main` was compared read-only: `git show main:`, `git ls-tree -r main`, `git cat-file` presence checks and `git diff HEAD main` on four speech and media files. `main` holds 117 commits this worktree lacks.
- LU clone: `<external>/locally-uncensored`, tag `v3.0.6` (commit `bce78481`). Read with Read, Grep and `git ls-files` only. No LU script, binary, npm, cargo or network access was used. `VOICE.md` and source comments are treated as documented claims, not as proof.
- PaRuX code was read with Serena symbol overviews and narrow Grep. No build or test was run, because another worktree is testing. The plan and `docs/*` were used only as claim sources (section 8).
- Evidence levels: `static` = code read at the cited lines; `unit_tests` = a named test class exists (attribute count given, not executed here); `e2e_real` = a real run recorded by the plan or a doc (not re-run here).
- Clean-room: every behavioural specification below is written in our own words. Only public identifiers, endpoint paths, file names and ComfyUI API names appear. No LU code, prompt text or long string is reproduced.

## 3. Headline findings

1. **P0, cancellation does not reach ComfyUI.** `ComfyWorkflowRunner.SubmitAndWaitAsync` (lines 457-520) cancels only PaRuX's own HTTP waits and progress socket. It never calls ComfyUI `/interrupt` or removes the prompt from `/queue`. Only the Ref2VA executor sends a best-effort `/interrupt` (`Ref2VaManagedExecutor.cs:180`, `339-342`). LU sends a per-prompt queue delete and interrupts only when that prompt is the running one (`comfyui.ts:2124`, `2148-2160`).
2. **Continuous voice exists only on Android.** The Windows App has no capture path: a grep for AudioGraph, WaveIn, MediaCapture and microphone finds nothing under `src/PaRuX.App`. The Android Live Voice loop exists (`ChatViewModel.kt:189-241`, `LocalVoiceEngine.kt:104-365`), but no device run is recorded and no test names endpointing or barge-in.
3. **Video is one fixed family.** PaRuX runs Wan 2.2 TI2V-5B from one template, with real multi-clip continuity. LU chooses among about ten families from installed files and node availability. PaRuX has no user start-image input and no managed download of the three Wan component files.
4. **Speech engine hygiene is weak on this branch.** The install is unpinned and CUDA-only (`SpeechService.cs:67`, `71`). STT hard-codes `device=0` (`:305`). `PrewarmAsync` has no caller (`:78-86`). Workers stay resident with no idle release. LU pins every voice file by revision and sha256 and shuts its engine down after five idle minutes (`voice-session.ts:100`).
5. **Local `main` already fixes speech defects that this branch lacks.** HEAD calls Kokoro with the default newline-only split (`ContinuousTtsWorker.cs:337`), so a single paragraph is one chunk and first audio waits for the whole synthesis. `main` splits at sentence ends. HEAD also installs `misaki[en]` without the spaCy English model, which `main` pins as a wheel (`main` `SpeechService.SpacyModelRequirement`). Its code comment says the lazy download failed in the managed venv during a BIC-13 live run. `main` also has a cancellation integration test and BIC-13 measurement scripts (`tools/bic13/`), none of which exist at HEAD.
6. **PaRuX strengths are real and tested.** Coordinator leases, bounded job retention, a managed ComfyUI runtime with rollback, a strict streaming protocol, Wan continuity with owned-output checks, Gaming hard-off, and an engine race with quality evidence.

## 5. Top 10 prioritised proposals

1. **P0. Propagate cancellation to ComfyUI.** On cancel, remove a pending prompt from `/queue`; send `/interrupt` only when it is running; keep the execution gate closed until ComfyUI reports the prompt gone. Start from `Ref2VaManagedExecutor.InterruptBestEffortAsync` (lines 339-342) and add the queue step. Tests with a fake ComfyUI server: cancel while pending, while running, and between Wan clips.
2. **P1. Port `main`'s speech fixes.** Sentence-level Kokoro split in the streaming worker, and the pinned spaCy wheel in `SpeechPackages`. Port `SpeechInstallPackagesTests` and `ContinuousSpeechCancellationIntegrationTests` from `main`. Measure first audio with `tools/bic13/measure_tts_stream.py` from `main`.
3. **P1. Barge-in without restart.** Add a cancel operation to the worker protocol that stops generation and keeps the model loaded. Keep the process kill as fallback. Acceptance: the follow-up turn meets a stated first-audio budget and no frame from the cancelled turn reaches the client.
4. **P1. Make Android voice testable.** Extract endpointing and barge-in into pure state machines with unit tests on synthetic frames. Keep pre-roll for the capture that follows a barge-in. Write a device runbook; no "done" claim before a device run.
5. **P1. Windows voice MVP without tools.** Capture, endpointing, streamed TTS, barge-in, and Gaming and cancel semantics, reusing `SpeechClient` streaming and Core chat. Tools wait for an approval model.
6. **P1. Speech lifecycle.** Wire `PrewarmAsync` to explicit user actions. Add idle release (configurable, default five minutes as LU documents) that also yields to Gaming Mode. Lock packages. Remove `device=0` and add device detection and a CPU path.
7. **P1. Family registry for video.** Replace the fixed template with per-family records: required components, node names, frame rule, audio-with-video flag, and an unavailable reason. Start with Wan 2.2 5B, then one second family.
8. **P1. Start-image path.** Expose the internal `AddWanStartImage` route in the Create video panel and map OpenAI `input_reference` to it. Enforce size and aspect rules.
9. **P1. Component manifest for media families.** Pinned revisions and sha256 for the Wan 2.2 UNET, UMT5 and VAE; a Model Hub install action; an actionable missing-component error. Do not copy LU's floating URLs.
10. **P2. Spoken-reply quality.** Clause-level first chunk, thinking removed before TTS, a Windows read-aloud control on the v2 stream, and time to first audio reported per turn.

Not in the top 10, by design: music generation (licence review first), talking-head adoption (licence and end-to-end run first), and video race (needs independent quality criteria).

## 6. Risks

- **Licence.** LU is AGPL-3.0 and PaRuX is MIT, so this audit stays at spec level. LU's voice notice covers CC BY 4.0 and CC0 voices. The plan notes MiniMax H3's community licence excludes the EU (plan 2858). LU's own test asserts YuE2 is non-commercial. Parakeet and LatentSync licences are not recorded in repo docs; Kokoro is recorded as Apache-2.0 (`docs/audio-model-decisions.md:30`).
- **VRAM.** Default Wan at 1280x720 peaks near 15.9 of 16.3 GiB (plan 2858). A resident speech worker (doc estimate 2-3 GB for Kokoro) competes with it. No speech-worker admission was found.
- **Unbounded GPU work after cancel** (row 13) can invalidate the admission model.
- **Reproducibility and supply chain.** Unpinned speech packages, the cu128 torch index, and LU's floating component URLs all make rebuilds non-reproducible.
- **Latency claims.** LU's VOICE.md numbers come from its own Windows and Mac runs; PaRuX's plan numbers come from one machine. Neither was re-run here.
- **Endpointing.** Android echo-cancel availability varies by device; energy endpointing can trigger on music or television.
- **Port.** `127.0.0.1:8188` is hard-coded (`ComfyWorkflowRunner.cs:475`, `693`).
- **Branch drift.** Several speech fixes and their evidence exist only on local `main`. A release cut from HEAD would miss them.

## 7. Open questions

- Does PaRuX restart or reset ComfyUI when a job times out or is cancelled? `LocalAiProcessManager` was not traced. If it does, row 13 is less severe, but the cancel still does not reach ComfyUI's queue.
- Does Kokoro `KPipeline` (`SpeechService.cs:331`) use CUDA automatically in the managed venv, since no device is passed?
- Which surface is the first-release voice target: Windows, Android, or both?
- Is the Parakeet weight licence acceptable for shipping? It is not recorded in repo docs.
- Where are the artifacts behind the BIC-13 claims, given that `tools/bic13/` exists only on `main`?
- Does local `main`'s `CreateWorkspaceView` (111 lines different from HEAD) change the TTS playback path? It was not reviewed in full.
- Should every new family adopt an "unavailable with reason" rule before more models are added?
