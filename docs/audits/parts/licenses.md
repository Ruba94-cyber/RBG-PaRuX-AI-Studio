# Licences and compliance: clean-room audit part (domain: licenses)

Status: part file for the PaRuX competitive audit, 2026-10-19. Not committed. Behavioural specification only: no Locally Uncensored (LU) source text, prompts, tables or algorithms are reproduced. Identifiers, file names and public endpoint names are cited for traceability.

Subject: LU v3.0.6 (tag v3.0.6, commit bce78481; external working copy outside this repository; the installed program folder was listed read-only and nothing was run) versus PaRuX (branch feature/parux-competitive-integration-20261019, HEAD 117fcf7). Paths are relative to the PaRuX worktree root unless marked LU.

## 1. Scope

- LU: its own licence and copyright lines, bundled and fetched binaries, npm and Cargo dependency licences, shipped notices, model and voice licence terms, and what the installed program folder contains.
- PaRuX: LICENSE, THIRD_PARTY_NOTICES.md, OPEN_SOURCE_PROVENANCE.md, docs/AGENT_UPSTREAM_REUSE_AUDIT.md, CONTRIBUTING.md, installer and MSI payload, NuGet and Gradle graphs, runtime lock, the Full Offline bundle script, the model licence consent gate and the provenance rules.
- Out of scope: runtime behaviour, UI quality, test results. No build, no test run, no npm, cargo or dotnet, no network, no LU script or binary executed.

## 6. What AGPL-3.0 means for PaRuX (engineering reading, not legal advice)

- Copying LU code, prompts, tables, identifiers or algorithms into PaRuX is not permitted in practice: the copied portion stays under AGPL-3.0 and the MIT grant cannot cover it (AGPL sections 5(c) and 6).
- Bundling LU binaries (locally-uncensored.exe, lu-llama-server.exe, resources/voice_loop) would make the installer an AGPL distribution with corresponding-source duties. Not recommended.
- Linking or in-process sharing: LU is an application, not a library, and a shared address space is a combined work. Keep LU in its own process.
- Network use (section 13) applies to a modified LU version that users interact with remotely. Running an unmodified LU and calling it over HTTP as a separate program does not by itself put PaRuX under the AGPL. This is an engineering reading and needs legal review.
- Separate unmodified binary: allowed, with LU's licence notice shown and no implication that PaRuX authored it.
- Behavioural specification: allowed when the author does not copy source and the implementer does not read LU source. Record the spec author, reviewer and LU revision (v3.0.6, commit bce78481) in OPEN_SOURCE_PROVENANCE.md.
- GPL-3.0 components (ComfyUI, FFmpeg builds, possibly piper-tts): the same process-boundary reasoning applies. Keep them separately installed and show their licences in the UI (R5, R9).

## 8. Risks

- A public MSI whose notice misstates Microsoft terms and the bundled binaries damages credibility and creates compliance exposure (R1, R2).
- Notice drift from the real NuGet and Gradle graphs (R3, R13, R20).
- The Full Offline bundle could be distributed with model weights whose licence texts are missing (R21).
- Managed runtimes and FFmpeg builds installed on user action without recorded licences (R4, R5, R9).
- Any copied LU code would bring AGPL-3.0 into the MIT distribution (blocking).
- Model licences from Hugging Face cards are publisher declarations. PaRuX treats them as workflow policy, not legal verification; that should stay visible in the UI (R6).
- LU's own gaps (no licence text for its MIT llama.cpp DLLs, no notices for its npm front-end, piper-tts unpinned and unlisted, HeyGen-derived preview images without a record) must not be copied as practice.
